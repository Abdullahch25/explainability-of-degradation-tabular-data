# Intersection of Explainability and Degradation in Tabular Data

Can SHAP feature importance help predict how much a model's performance will degrade when its input data is corrupted?

This project trains Random Forest classifiers on 13 OpenML-CC18 datasets, corrupts their test data in controlled ways (targeting features by SHAP importance), measures the resulting performance drop and then trains meta-models to predict that drop. SHAP-informed meta-models are compared against a baseline that only knows the corruption severity.

## Key result

5-fold cross-validated prediction of performance drop (Step 13):

| Meta-model | RMSE | R² | Pearson r |
|---|---|---|---|
| Severity-only baseline | 0.0456 | 0.112 | 0.335 |
| Severity + severity² baseline | 0.0457 | 0.111 | 0.333 |
| Heuristic (SHAP × severity) | 0.0426 | 0.227 | 0.476 |
| Linear regression (full features) | 0.0369 | 0.420 | 0.649 |
| **Random Forest regressor** | **0.0260** | **0.712** | **0.845** |

Adding SHAP-based features raises explained variance from about 11% (severity only) to about 71% (Random Forest meta-model).

## Datasets

13 classification datasets from OpenML-CC18 without missing values, in three size groups:

- **Small:** diabetes, vehicle, credit-g, qsar-biodeg, cmc
- **Medium:** segment, ozone-level-8hr, spambase, phoneme, satimage
- **Large:** bank-marketing, electricity, connect-4

## Pipeline

| Step | Script | What it does |
|---|---|---|
| 1 | `step1_dataset_selection.py` | Filter OpenML-CC18 and select 13 datasets |
| 2 | `step2_data_loading.py` | Download raw data via the OpenML API |
| 3 | `step3_preprocessing.py` | Imputation, encoding, scaling, train/test split |
| 4 | `step4_baseline_training.py` | Train a Random Forest per dataset |
| 5 | `step5_baseline_evaluation.py` | Accuracy, F1, AUC on the clean test set |
| 6 | `step6_shap_importance.py` | SHAP TreeExplainer feature importance |
| 7 | `step7_corruption_design.py` | Corruption plan: high/low SHAP tiers × 7 corruption types × severities 10/30/50% |
| 8 | `step8_data_corruption.py` | Apply corruptions (Jenga): MCAR/MAR/MNAR missingness, Gaussian noise, extreme values, value swap, scaling |
| 9 | `step9_performance_after_corruption.py` | Performance drop = baseline − corrupted |
| 10 | `step10_drift_measurement.py` | Distribution drift via per-feature two-sample KS tests (SciPy) |
| 11 | `step11_meta_model.py` | Meta-models: SHAP × severity heuristic, linear regression, RF regressor |
| 12 | `step12_severity_baseline.py` | Severity-only baselines |
| 13 | `step13_evaluation.py` | Compare all models (RMSE, MAE, R², Pearson r), with breakdowns by tier, severity and corruption type |
| 13 | `step13_fold_metrics.py` | Per-fold CV metrics for all models (error bars in the figures) |

`results_visualization.ipynb` produces the figures from the result CSVs.

Each step writes its output to `stepN_*.csv` files, which are included in the repo. The raw/processed data, trained models, SHAP values and figures are not committed they are regenerated by running the pipeline.

## Running it

Requires Python 3.11+ (developed on 3.14).

```bash
pip install -r requirements.txt

python step1_dataset_selection.py
python step2_data_loading.py
# ... run each step in order through
python step13_evaluation.py
python step13_fold_metrics.py
```

Step 10 will additionally run alibi-detect's `KSDrift` if that package is installed, but the published results use only the SciPy KS test (the `alibi_*` columns in `step10_drift_results.csv` are empty).

Then open `results_visualization.ipynb` to regenerate the figures (saved to `report_figures/`). `ipykernel` is enough to run it in VS Code. For the browser interface, also `pip install notebook`.

Notes:
- Steps 1–2 download the datasets from OpenML, so an internet connection is needed.
- The generated data and models take about 1.7 GB of disk space.
